# 妈妈的菜谱 · 家庭点餐 + 菜谱系统

一个纯静态的轻量互动网站：**大厨选菜 → 食客选菜 → 食客导出编码 → 大厨导入 → 找到共同选择 → 看菜谱**。

没有框架、没有依赖、没有构建步骤。双击 `index.html` 就能用，也可以直接丢到 GitHub Pages 上给手机访问。

---

## 一、怎么用

### 本地看效果
双击 `index.html` 即可（Chrome / Edge / Safari 都行）。

### 手机上用
两种方式：
1. **部署到 GitHub Pages**（推荐，见下一节），然后把网址发给妈妈和食客。
2. 把整个文件夹拷到手机里用浏览器打开 `index.html`（iOS 上稍麻烦，Android 可行）。

> 建议部署成网址。因为大厨和食客是**两台不同的手机**，各自的选择保存在各自手机本地，中间靠「导出 / 导入」这一行文本传递。

## 二、部署到 GitHub Pages

网站是纯静态的，三种方式任选。**推荐方式一：文件夹里已经放好了一键脚本，双击就行，不需要安装 git。**

### 方式一：一键脚本（推荐，连 Pages 都帮你开）

文件夹里的 `publish.bat` + `publish-to-github.ps1` 就是发布工具：它用 GitHub 官方 API 把网站文件传上去并开启 Pages，**不需要 git，也不需要 github 命令行工具**。

1. **先建仓库**：<https://github.com> 登录 → 右上角 **+** → **New repository** →
   名字填 `mama-recipe` → 选 **Public** → 下面几个选项**都不要勾** → **Create repository**。
2. **生成访问令牌**：右上角头像 → **Settings** → 左下 **Developer settings** →
   **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)** →
   **只勾 `repo` 这一项** → 生成 → 复制那串字符（只显示一次，关掉就看不到了）。
3. 回到这个文件夹，**双击 `publish.bat`**。
4. 按提示粘贴仓库地址（`https://github.com/你的用户名/mama-recipe`）和令牌（**输入时不显示**），确认上传。
5. 脚本会把网站文件全部传上去、自动开启 Pages，最后打印出你的网址。等 1～2 分钟即可访问。

> · 令牌只在这一次运行里使用，脚本**不会**把它写进任何文件。用完可以在 GitHub 上删掉它。
> · **以后更新**：改完菜谱再双击一次 `publish.bat` 就行（有则更新、无则新建）。
> · 连不上 GitHub 时（国内网络有时访问不了 `api.github.com`），可以带代理运行：
>   `powershell -ExecutionPolicy Bypass -File publish-to-github.ps1 -Proxy http://127.0.0.1:7890`
> · 只想看看会传哪些文件、不做任何网络请求：加 `-DryRun`。

### 方式二：网页上传（完全不碰令牌）

1. 打开 <https://github.com>，登录（没有账号就注册一个，免费）。
2. 右上角 **+** → **New repository**。
   - **Repository name** 填 `mama-recipe`（或任意名字，注意只能用英文/数字/短横线）
   - 选 **Public**（Private 仓库用不了免费的 Pages）
   - 下面的 "Add a README file" 等选项**都不要勾**
   - 点 **Create repository**
3. 新仓库页面上点 **uploading an existing file**（或地址栏直接访问 `https://github.com/<你的用户名>/mama-recipe/upload/main`）。
4. 打开本机这个文件夹 `菜谱项目`，**选中里面的所有内容**（`index.html`、`README.md`、`css` 文件夹、`js` 文件夹、`.nojekyll`），
   把它们**拖进网页的虚线框**里（注意：拖的是文件夹**里面的内容**，不是 `菜谱项目` 文件夹本身——`index.html` 必须落在仓库根目录）。
5. 页面下方 **Commit changes**。
6. 进仓库的 **Settings** → 左侧 **Pages** → **Source** 选 `Deploy from a branch`，
   **Branch** 选 `main` + `/ (root)` → **Save**。
7. 等 1～2 分钟，访问 `https://<你的用户名>.github.io/mama-recipe/` 就是你的网站了。手机浏览器打开这个网址即可用。

> `.nojekyll` 是 Windows 里的隐藏点文件，资源管理器里能看到（图标是白的那个）。拖不进去也没关系，项目里没有下划线开头的目录，不影响。

### 方式三：命令行（装了 Git 之后）

需要先装 Git：<https://git-scm.com/download/win>（一路下一步即可）。然后在 `菜谱项目` 文件夹里执行：

```bash
git init
git add .
git commit -m "妈妈的菜谱"
git branch -M main
git remote add origin https://github.com/<你的用户名>/mama-recipe.git
git push -u origin main
```

推送时会要求登录 GitHub（浏览器弹窗授权即可）。之后第 3 步的 Pages 设置同上。

### 以后怎么更新

- **方式一（脚本）**：改完文件再双击一次 `publish.bat`，最省事。
- **方式二（网页）**：仓库页面 → **Add file** → **Upload files** → 把改过的文件拖进去 → Commit。
- **方式三（git）**：`git add . && git commit -m "更新菜谱" && git push`。
- 三种方式都只要等半分钟左右 GitHub 重新发布，然后手机刷新（必要时清一下浏览器缓存）。

> 所有路径都是相对路径，所以放在仓库子目录（`xxx.github.io/mama-recipe/`）能正常打开；同理，整个文件夹拷到任何静态服务器上都能用。

## 四、怎么加菜 / 改菜（只改 `js/data.js`）

### 1. 改分类顺序
`CATEGORIES` 数组的顺序就是全站顺序，它同时决定：

- 点餐页左侧分类栏顺序
- 菜品滚动时左侧高亮的当前分类
- 菜谱查询页的分类顺序
- 共同选择的排序
- 菜品编码里的分类字母（`A`/`B`/`C`… 按数组位置自动对应）

```js
var CATEGORIES = [
  { letter: 'A', name: '主食' },
  { letter: 'B', name: '凉菜' },
  { letter: 'C', name: '热菜' },
  { letter: 'D', name: '汤类' },
  { letter: 'E', name: '饮品' }
];
```

### 2. 编号规则
`code` = **分类字母 + 三位数字**，每个分类各自从 `001` 开始往下排：

| 分类 | 现在有几道 | 编号区间 |
| --- | --- | --- |
| A 主食 | 5 道正式菜谱 | `A001`～`A005` |
| B 凉菜 | 1 条「示例」占位 | `B999` |
| C 热菜 | 1 条「示例」占位 | `C999` |
| D 汤类 | 1 条「示例」占位 | `D999` |
| E 饮品 | 1 条「示例」占位 | `E999` |

「示例」占位菜固定用 `999` 结尾，是为了**不占正式编号**：以后往「凉菜」里加真菜，从 `B001` 开始编，加到 `B998` 都不会和占位菜撞号；那个分类有了真菜之后，把那条 `B999 示例` 整条删掉即可。
占位菜是可以正常点、正常导入导出的——它和其它菜一样有编码，只是正文写着「等有正式菜谱再来替换」。

### 3. 加一道菜（单一流程）
往 `DISHES` 里加一条即可：

```js
{
  code: 'C001',                 // 唯一编码，导出入库、匹配、共同选择全靠它
  category: 'C',                // 分类字母，必须在 CATEGORIES 里
  name: '可乐鸡翅',
  image: 'assets/images/C001.jpg',   // 没有图片就写 ''，自动用渐变+首字占位
  description: '小孩最爱',       // 点餐页显示在「C001」后面
  ingredients: ['鸡翅中 10 个', '可乐 1 罐'],   // 结构化保留，方便以后生成买菜清单
  steps: [                      // 菜谱正文，详情页自动编号 1. 2. 3.
    '鸡翅两面各划两刀，冷水下锅焯 2 分钟，捞出冲净。',
    '锅中少油，鸡翅煎到两面金黄。',
    '倒入可乐没过鸡翅，加 1 勺生抽、2 片姜，大火烧开转小火焖 15 分钟。',
    '大火收汁到浓稠挂在鸡翅上即可。'
  ],
  tips: ['收汁时勤翻动，糖分容易糊锅。'],   // 可选，详情页用淡橙底块显示「小贴士」
  douyinUrl: ''                 // 有抖音链接就填上，详情页显示「查看视频」，留空则整行隐藏
}
```

### 4. 分阶段菜谱（和面 / 调馅 / 包制 / 蒸制…）
原文是「一、和面醒发 → 二、调拌肉馅 → 三、包制包子 → 四、蒸制出锅」这种写法的，
用 `sections` 字段，页面上就是**每个阶段一个小标题、编号各自从 1 开始**，和原文一致；
只有一个流程的菜继续用上面的 `steps` 平铺即可。`sections` 优先于 `steps`，两者写一个就行：

```js
{
  code: 'A006',
  category: 'A',
  name: '葱花饼',
  ingredients: ['面粉 300 克', '葱花 适量'],
  sections: [
    { title: '一、和面',   steps: ['面粉加温水揉成团，醒 20 分钟。'] },
    { title: '二、擀饼',   steps: ['擀成薄片，抹油撒葱花。', '卷起后压扁，再擀开。'] },
    { title: '三、烙制',   steps: ['中小火两面烙金黄即可出锅。'] }
  ],
  tips: ['和面用温水，饼才软。']
}
```

> 现在的 `A001 鲜肉灌汤包`、`A002 家常半发面小油饼`、`A003 薄皮韭菜馅饼` 用的就是 `sections`；
> `A004 家常大饼`、`A005 蔬菜小饼` 原文就是一条直线，用的是 `steps` + `tips`。

### 5. 图片方案（已确认）
**不加真实图片**，就用内置的「渐变底色 + 菜名首字」占位图——颜色按菜品编码生成，同一道菜每次颜色都一样。
所有菜的 `image` 都写成空字符串 `''`，所以页面不会去请求任何图片，控制台是干净的。
哪天想给某道菜加图：把图片按编码命名放进 `assets/images/`（例如 `assets/images/A001.jpg`），再把这道菜的 `image` 改成 `'assets/images/A001.jpg'` 就行，其它地方一律不用动。

### 6. 现在站里有哪些菜
正式菜谱来自 `菜谱2.docx`（妈妈发来的第一批，都是面食，全部归到「主食」），**原来的 15 道示例菜品已全部删除**：

| 编码 | 菜名 | 阶段 | 步骤总数 |
| --- | --- | --- | --- |
| `A001` | 鲜肉灌汤包 | 和面醒发 / 调拌肉馅 / 包制包子 / 蒸制出锅 | 14 |
| `A002` | 家常半发面小油饼 | 和面 / 做油酥 / 擀饼 / 烙饼（＋5 条小贴士） | 17 |
| `A003` | 薄皮韭菜馅饼 | 和面醒发 / 调拌馅料 / 包制馅饼 / 烙制出锅（＋5 条小贴士） | 15 |
| `A004` | 家常大饼 | 单一流程（＋成品特点） | 7 |
| `A005` | 蔬菜小饼 | 单一流程（＋成品特点） | 9 |

五个菜谱都带上了原文里的抖音「查看视频」链接；正文里的用量按站内习惯写成「面粉 300 克」这种顺序，内容与原文一致。
「凉菜 / 热菜 / 汤类 / 饮品」四个品类暂时各放了一条 `示例` 占位，等有正式菜谱再替换。

### 7. 改错了怎么办：自带数据体检
改完 `data.js` 刷新页面，如果哪里写错了，**按 F12 打开浏览器控制台**会直接列出问题，例如：

```
[data] 菜品数据有 2 处问题：
· C001：编码首字母和 category（A）对不上
· A003：还没有菜谱正文（sections 或 steps）
```

也可以在控制台手动执行 `MR.data.validate()` 随时体检。会检查：编码格式（分类字母 + 三位数字）、编码是否重复、分类字母是否存在、编码首字母与分类是否一致、菜名 / 描述是否为空、正文（`sections` 或 `steps`）是否有内容且没有空阶段、图片路径是否符合 `assets/images/编码.jpg` 的约定。

> 检查结果只是提示，不影响网站正常显示——写漏了描述，点餐页那一行就空一块而已。

## 五、大厨与食客怎么交换选择

1. **食客**：点餐 → 购物袋 → 去结算 → 确认结算 → 进入菜谱页，点「导出」，复制这一行：
   ```
   2026年05月03日21:36｜A008 B027 C001
   ```
   格式固定为「结算时间｜菜品编码 菜品编码 …」，**编码数量不限**。

2. **大厨**：菜谱页点「导入」→ 把上面那行粘进输入框（✓ 会由灰变绿）→ 点 ✓
   - 出现 **一键全选**：把食客点的菜一次性加进「大厨选择」
   - 也可以只点某几行右边的 **＋**，单独把你同意的菜加进来
   - 下面是浅灰分割线 → 结算时间 → 点餐信息（单行卡片，不显示描述）

3. 回到「大厨选择」或「食客选择」页签，如果双方有相同的菜，**最上方会出现「共同选择」**，按全站分类顺序排列；没有交集时整块不出现。

4. **大厨结算时也会自动复制一份**：点「确认结算」的那一刻，按食客完全一样的格式把这次大厨自己选的菜写进剪贴板（`2026年05月03日21:36｜A008 B027 C001`）。没有任何按钮、没有任何提示，复制失败也完全静默；「结算成功」那个提示保留。想转发给别人时直接粘贴就行。

> 食客发来的编码如果在菜品数据里找不到，导入页会明确提示是哪几个编码，不影响其他的菜。

## 六、状态保存在哪里

所有状态（身份、大厨选择、食客选择、导入结果、每个菜谱的阅读位置）都保存在**当前浏览器本地**（`localStorage`，键名 `mama-recipe-v1`）：

- 刷新、关掉浏览器再打开都不会丢
- **每台设备各自独立**，这正是「大厨和食客各在自己手机上操作、用一行文本交换结果」的基础
- **两个身份各自保存自己的选择与结算时间**，来回切身份不会丢任何一方的数据
- **每次重新进入网站都先到身份选择页，选完身份一律进点餐页**——不因为上次结算过就直接跳进菜谱页，不论有没有缓存
- 想清空重来：浏览器控制台执行 `MR.store.reset()`，或清除该站点的本地存储
- 老版本存下的数据会自动迁移，不用手动清空
- 唯一要手动清一次的情况：**这一批正式菜谱替换掉了原来的示例菜品**，`A001` 这类编码现在指向的是新菜。如果之前在旧版本里点过菜，历史选择里的编码会按新菜显示（数据里没有的编码会自动忽略）。重新选一遍菜、或在控制台执行一次 `MR.store.reset()`，就干净了。

## 七、需求对照

| 需求 | 实现 |
| --- | --- |
| 一份菜品数据多处复用 | 全部页面只从 `js/data.js` 读取，没有第二份菜品副本 |
| 编码优先 | 导入 / 导出 / 匹配 / 共同选择全部基于 `code`，与菜名无关 |
| 分类统一 | 分类顺序由 `CATEGORIES` 决定，页面里不写死 |
| 选择与菜品分离 | 状态里只存编码数组，改菜名 / 换图 / 改菜谱不影响任何选择记录 |
| 首页 | 每次打开网站都先到这里（这一屏不标「当前」）；只有大厨 / 食客两个入口，选中后显示「欢迎大厨」+ 进度条，走完进入点餐页——**不论有没有缓存，都从这一步重新开始** |
| 点餐页 | 左侧固定分类栏 + 右侧一条连续菜品流；行间浅灰实线；`图｜菜名 / 编码 描述｜＋` |
| 滚动联动 | 右侧滚动位置决定左侧当前分类，点左侧平滑滚到对应分类 |
| 到底提示 | 灰色「到最最最底下了！」 |

## 八、几个和原始需求不同的小地方（都已尽量贴近，可随时改）

1. **顶栏多了几个低调的文字入口**：需求里没有，但真机上会走进死路——结算后进了菜谱页就回不了点餐页（菜谱页加了「继续点餐」）；选完身份之后没有回头路（点餐页和菜谱页都加了「切换身份」）；选了一堆菜想一次清掉做不到（菜谱页加了「清除全部」）；每次进入都从点餐页开始、想直接看菜谱也没入口（点餐页加了「看菜谱」）。都是 12px 灰色小字，不抢视觉，放不下会自动换行。首页会给当前身份标一个「当前」。
2. **菜谱正文里带用量**：详情页结构严格按需求（菜名 → 抖音 → 虚线 → 步骤 → 虚线 → 编码），没有单独的「食材」区块，所以把用量写进了步骤文字里；`ingredients` 字段仍然保留，以后想单独展示随时可用。
3. **购物袋为空时点击**只弹一句提示，不展开空抽屉。
4. **分类标题在点餐页会吸顶**（`position: sticky`），方便随时知道滑到哪一类。
5. **未结算就进导出页**会提示先去结算，因为导出格式要求带上结算时间。
6. **查询页的分类只用一条虚线**：原始需求的示意图里，分类名上下各有一条虚线；实际做出来之后，上方那一条已经足够起分隔作用，下方那一条已按你的要求去掉（菜谱详情页正文上下的虚线保持不变）。
7. **「批量删除」在大厨的两个页签都有**：需求里只写了"大厨在菜谱查询页面拥有批量删除"。放到两个页签上，一是两边行为一致（都是删当前列表里的菜），二是顶栏按钮数量一致、高度不变，切页签时页面不会上下跳。
8. **页签改成等宽分段控件**：选中时文字加粗，如果按钮宽度跟着变，会把它旁边的按钮顶开、页面一抖。改成等宽后加粗不再影响布局，高亮由一块会滑动的高亮层表示。
9. **菜谱正文多了一层「阶段小标题」和「小贴士」**：第一批正式菜谱（灌汤包、小油饼、韭菜馅饼）原文是「一、和面醒发 / 二、调拌肉馅 / 三、包制包子 / 四、蒸制出锅」这种分阶段写法，如果直接拉平成 1～14 条连续编号，阶段的分界就没了。所以正文的位置、结构、虚线都没动，只是允许按原文分成几段，每段自己从 1 开始编号；原文末尾的「小贴士 / 成品特点」放在正文下面一块淡橙底里，和步骤区分开。单一流程的菜（家常大饼、蔬菜小饼）看起来和以前完全一样。
10. **空白品类放了「示例」占位菜**：第一批正式菜谱全是面食，都归到「主食」；「凉菜 / 热菜 / 汤类 / 饮品」四个品类先各放一条名字叫「示例」的菜占着位置（编码用 `X999`，不占正式编号），点进去正文会说明怎么替换成真菜谱。
11. **序号里的用量写法统一了顺序**：原文「300克普通面粉」在站里写成「普通面粉 300 克」，和原有菜品风格一致，数字与内容没有改动。
